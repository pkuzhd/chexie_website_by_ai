# UserInfo表结构介绍文档

## 1. 表结构概览

UserInfo表是论坛系统的核心用户信息表，用于存储用户的基本信息、认证信息、个人资料和统计数据。该表设计用于支持用户管理、权限控制、个性化设置和用户行为分析等功能。

## 3. 字段详细说明

### 3.1 核心认证字段

| 字段名    | 说明                                                                 |
|-----------|----------------------------------------------------------------------|
| username  | 用户名，用于用户登录和身份识别，非空且唯一                            |
| password  | 用户密码，建议使用MD5或更安全的哈希算法存储，非空                    |
| token     | 认证令牌，用于无状态认证机制（如JWT）                                |
| tokentime | 令牌生成时间或过期时间，用于令牌有效期验证                            |
| userid    | 用户ID，自增主键，是系统内部识别用户的唯一标识                        |

### 3.2 个人基本信息

| 字段名  | 说明                                                                 |
|---------|----------------------------------------------------------------------|
| sex     | 用户性别，通常使用"男"、"女"或"保密"等取值                          |
| icon    | 用户头像，存储头像文件路径或Base64编码的图片数据                     |
| intro   | 用户自我介绍，最多500字符                                             |
| hobby   | 用户爱好，最多50字符                                                  |
| qq      | 用户QQ号码，最多12位                                                 |
| mail    | 用户邮箱地址，用于密码找回和系统通知                                  |
| place   | 用户所在地，用于地域统计和个性化推荐                                  |

### 3.3 个性化设置

| 字段名 | 说明                                                                 |
|--------|----------------------------------------------------------------------|
| sig1   | 用户签名1，最多1000字符，用于论坛帖子底部显示                        |
| sig2   | 用户签名2，最多1000字符                                              |
| sig3   | 用户签名3，最多1000字符，允许用户设置多个签名选择使用                |

### 3.4 用户活动统计

| 字段名 | 说明                                                                 |
|--------|----------------------------------------------------------------------|
| regdate | 用户注册时间，通常使用YYYY-MM-DD格式                                  |
| lastdate| 用户最后登录时间，用于判断用户活跃度                                  |
| lastip  | 用户最后登录IP地址，用于安全审计和地理位置分析                        |
| post    | 用户发帖数量统计                                                     |
| reply   | 用户回帖数量统计                                                     |
| water   | 用户灌水帖数量统计                                                   |
| sign    | 用户签到次数统计                                                     |

### 3.5 用户等级与积分

| 字段名 | 说明                                                                 |
|--------|----------------------------------------------------------------------|
| star   | 用户星级等级，用于标识用户的活跃程度和贡献值                          |
| score  | 用户积分，初始值为0，通过发帖、回帖等行为获得                         |

### 3.6 权限与状态

| 字段名     | 说明                                                                 |
|------------|----------------------------------------------------------------------|
| rights     | 用户权限等级，用于控制用户在系统中的操作权限                          |
| extr       | 额外权限标记，用于标识特殊用户组或临时权限                            |
| newmsg     | 新消息提醒标记，用于通知用户有未读消息                                |
| onlinetype | 用户在线状态类型，如"在线"、"离线"、"隐身"等                          |

### 3.7 其他信息

| 字段名   | 说明                                                                 |
|----------|----------------------------------------------------------------------|
| lastpost | 用户最后发帖信息，用于快速定位用户的最新动态                          |
| nowboard | 用户当前所在板块ID，用于记录用户的浏览位置                            |
| logininfo| 用户登录信息，如登录设备、浏览器信息等，用于安全审计                  |
| code     | 验证码或临时代码，用于邮箱验证、密码找回等场景                        |
| other2-6 | 预留字段，用于系统扩展和未来功能需求                                  |

## 4. 表设计特点与使用建议

### 4.1 设计特点

1. **完整性**：包含了用户管理所需的全部基础字段
2. **可扩展性**：预留了多个额外字段用于未来功能扩展
3. **性能优化**：对常用查询字段（username, token）建立了索引
4. **安全性**：密码字段独立存储，便于加密处理
5. **灵活性**：支持多种用户个性化设置

### 4.2 使用建议

1. **密码安全**：始终使用安全的哈希算法（如bcrypt）存储密码，避免明文存储
2. **令牌管理**：定期清理过期的token记录，确保系统安全性
3. **数据类型**：时间字段建议使用datetime类型替代varchar，便于时间计算和排序
4. **索引优化**：根据查询需求为常用字段（如mail, regdate）添加索引
5. **数据验证**：在应用层对用户输入进行严格验证，确保数据完整性
6. **权限控制**：基于rights字段实现细粒度的权限控制机制

## 5. 与其他表的关系

UserInfo表作为论坛系统的核心表，与其他表存在以下主要关系：

1. **与threads表**：一对多关系，一个用户可以发布多个主题帖
2. **与posts表**：一对多关系，一个用户可以发布多个回帖
3. **与messages表**：一对多关系，一个用户可以发送或接收多条私信
4. **与attachments表**：一对多关系，一个用户可以上传多个附件
5. **与sign表**：一对多关系，一个用户可以有多个签到记录

## 6. 典型应用场景

1. **用户登录认证**：通过username和password验证用户身份，并生成token
2. **用户资料管理**：允许用户查看和编辑个人资料
3. **用户等级系统**：基于score和post等字段计算用户等级
4. **活跃度统计**：通过lastdate、post、reply等字段分析用户活跃度
5. **个性化推荐**：基于place、hobby等字段进行内容推荐
